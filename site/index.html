music-bot.ts — the entire Discord glue
import { Junie } from 'junie';

const junie = new Junie({
  nodes: [{ id: 'main', host: 'localhost', authorization: 'youshallnotpass' }],
  sendToShard: (guildId, payload) => client.guilds.cache.get(guildId)?.shard.send(payload),
});
junie.init(client.user.id);
client.on('raw', (packet) => junie.sendRawData(packet));
// that's it — discord.js, Eris, Oceanic, or your own sharder

Built around the way music bots actually die

Every feature below maps to a real 3am outage pattern, not a feature checklist.

⚡ Auto-failover

Node dies → players migrate to the healthiest node with voice, track, position and filters intact. autoFailover (default on), or player.setNode() for manual control.

🔄 Session resuming, self-healing

Configured on connect, verified on reconnect. A 404 on your session (Lavalink restarted) triggers a re-handshake and player rebuild — automatically.

🔀 Library-agnostic

Two callbacks are the whole contract. Typed events, requester generics, and raw packet forwarding keep you out of wrapper lock-in.

🧭 Penalty-based load balancing

Players, CPU saturation and frame loss scored per node, region-aware placement from Discord voice endpoints, parallel search fan-out against rate limits.

💿 Queue that survives restarts

Repeat modes, autoplay, shuffle, bounded history — plus a pluggable QueueStore and UnresolvedTracks that lazily resolve right before playing.

🎚 Every v4 filter, validated

Fluent chains, one round-trip applies, and presets: nightcore(), bassboost(), vaporwave(), eightD(), karaoke().
